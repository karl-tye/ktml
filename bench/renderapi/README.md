# ADR-0003 rendering-API benchmarks (synthetic set)

> **Frozen (2026-10-12).** ADR-0003 is Accepted with Hybrid H. The `a/` tree
> and its generator path were removed after the comparison; the module now
> keeps H and the B floor. The results below and in `results/` were measured
> with all three trees at KTML `e5d9670` and stay as the record.

This module holds the synthetic half of the
[ADR-0003 evaluation protocol](../../docs/adr/0003-rendering-api.md#evaluation-protocol):
`Static`, `Nested`, `ListHeavy`, `FormHeavy`, and `ScriptHeavy`. Each one has
five implementations:

- **A**, **H**, and **B**: the three candidate APIs generated by `gogen`
  (`Options.API` = `APIBound`, `APIStruct`, `APIDirect`), production variant
  (`//go:build !ktmldev`);
- **templ**: the templ `v0.3.1020` baseline;
- **handwritten**: plain Go writes, the lower bound.

It is a separate module, so templ never becomes a dependency of the main KTML
module.

## Layout

| Path | Contents |
| --- | --- |
| `ktml/{static,nested,cross,list,form,script}/` | KTML sources, written once |
| `a/…`, `h/…`, `b/…` | `gogen` output per candidate (`*_ktml.go`, `*_ktmlschema.go`), with the same package structure in each tree, so `cross` calls `nested` across packages in each one. Committed |
| `{a,h,b}/script/script_hand.go` | **hand-lowered** `ScriptHeavy` (see below) |
| `templ/`, `templ/tplui/` | templ baseline (`*.templ` and the committed `*_templ.go`); `tplui.Box` is the cross-package level |
| `handwritten/` | lower bound |
| `model/` | view types for templ and handwritten |
| `bench_test.go`, `fixtures_test.go`, `form_values_test.go` | byte-identity tests, fixtures, and benchmarks |
| `cmd/size/` | linked-size harness (build tags `sizeh`, `sizeb`; no tag is the baseline; `sizea` was removed with the A tree) |
| `scripts/` | `bench.sh` (protocol run), `size.sh` (size report), `summary.py` (README tables), `genform.py` (FormHeavy sources), `staticpage/` (Static copies) |
| `results/` | raw benchmark output, benchstat, and the size report |

## Benchmarks

| ID | Shape | Output |
| --- | --- | ---: |
| `Static` | a static page, no inputs (a fictional bicycle workshop's overview page) | 4,144 B |
| `NestedSame` | depth-8 chain of `Box [depth: integer, children: content]` filled through `children` at every level, same package | 371 B |
| `NestedCross` | the same chain built in package `cross` from `nested.Box`: every level is a cross-package call through the candidate's public API | 371 B |
| `NestedSlots` | depth-8 chain of `Panel [depth: integer, children: content, title: content]`: `children` plus one named slot per level | 1,067 B |
| `ListHeavy` | 1,000-item Keyed Repetition of `Entry` records, each with a 3-item nested keyed list of `Tag` and an optional `note` rendered under `if entry.note?` (half present) | 242,700 B |
| `FormHeavy` | 40 `Field` calls with string, integer, number, and boolean inputs; optional (`hint?`, `step?`) and defaulted (`kind`, `maxlength`, `required`, `disabled`) inputs set or omitted per field; values, labels, hints, and the CSRF token carry `<>&"'`; a `URL` form action | 15,303 B |
| `ScriptHeavy` | a `JSONValue` script element (raw `<`, `>`, `&` in the data, so the escaper works), a `TrustedScript` block, 40 links with `URL` and `TrustedURL` attributes, and about 7 KiB of high-escape text (about one byte in five escaped) | 37,309 B |

`ScriptHeavy` models a common page shape: a script element with JSON data,
followed by links and a lot of escaped text. Its content (a fictional lecture
deck) is invented.

Every implementation builds its props or arguments at the call site, as a
handler would. Fixtures are built once, outside the timed loop.

### Byte identity

`go test ./...` renders every benchmark with every implementation, into a
`*bytes.Buffer` and through a plain `io.Writer` without `WriteString`, and
fails unless all bytes are identical. This test is the protocol's pre-timing
check.

A few choices exist only to make templ write the same bytes:

- templ writes a space between adjacent inline nodes on separate source lines
  (an `if` counts as inline). `Field` therefore wraps its label and input in
  `div class="control"` and its step in `div class="extra"`, and templ writes
  the two links of a `ScriptHeavy` item on one line.
- templ writes `<script type="application/json">` contents as raw text, so it
  uses `templ.JSONScript`, which writes `id` before `type` and ends the JSON
  with the newline of `json.Encoder`. The KTML element uses the same attribute
  order, and the presenter's `ktml.JSONValue` ends with that newline.
- templ's trusted script goes through a `templ.ComponentFunc`, which is what
  `templ.Raw` is.
- templ has no optional or defaulted parameters: `TemplField` takes an empty
  hint and a zero step as absent. Its `Panel` title is filled with a
  `PanelTitle(text)` component.

### What each implementation does per render

- **A/H/B**: everything the ADR requires: `ctx.Err()` on entry to each
  component and before each repetition item, the Keyed Repetition preflight
  (`rt.StringKeys`/`rt.IntegerKeys`), required-content checks, typed errors,
  and the pooled `rt.Writer`.
- **templ**: templ's own runtime (pooled buffer, children context).
- **handwritten**: one pass, direct `WriteString` and run-based escaping, one
  allocation per page for number scratch. No context checks, no key
  preflight, no typed errors.

## Hand-lowered parts

The compiler does not lower `JSONValue` or `TrustedScript`. `ScriptHeavy` is
therefore hand-lowered in each tree (`{a,h,b}/script/script_hand.go`), in the
exact shape `gogen` emits for that API. It writes the two script elements with
`rt.JSONScript` and `rt.Script` and calls the generated `ScriptLinks`
statically, as `gogen` calls a same-package component. The KTML it stands for
is in the file's header comment. Everything else, including `ScriptLinks`
(`URL`, `TrustedURL`, high-escape text, Keyed Repetition), is generated.

## Regenerating

From the repository root:

```sh
# KTML trees (a, h, b) from ktml/**; without -update the test fails when stale
go test ./internal/generator/gogen -run RenderAPIBenchmark -update
```

From `bench/renderapi`:

```sh
python3 scripts/genform.py         # FormHeavy: KTML, templ, handwritten, fixture converters
go run ./scripts/staticpage        # Static: templ and handwritten copies of the KTML page
templ generate -path ./templ       # templ v0.3.1020
```

`genform.py` and `staticpage` write sources that the gogen step or templ then
compile. Run them in the order above, and run the gogen step again after
`genform.py`.

## Running

```sh
go test ./...                      # byte identity (not timed)
scripts/bench.sh                   # tests, then -bench . -benchmem -count=10 -cpu=1, then benchstat
scripts/size.sh results/size.txt   # generated source size and linked .text
python3 scripts/summary.py         # README tables from results/synthetic.txt
```

Benchmark names are `Benchmark<ID>/impl=<A|H|B|templ|handwritten>/w=<discard|buffer>`,
so `benchstat -col /impl results/synthetic.txt` compares the implementations
side by side. `w=buffer` is a `*bytes.Buffer` pre-grown to 1 MiB and reset
each iteration.

### Observations

- **A, H, and B are tied except on the nested benchmarks.** On `Static`,
  `ListHeavy`, `FormHeavy`, and `ScriptHeavy`, benchstat finds no significant
  difference between A, H, and B, except B being 6% faster on
  `ListHeavy/w=buffer` (p=0.011). The whole page is one static call chain in
  every API.
- **Content slots cost A and H 9 allocations and 1.3–1.8× B.** On the nested
  benchmarks, A and H store each `children` fill (a `ktml.ComponentFunc`
  closure) in a `ktml.Component` field. The closure escapes, which is 8
  allocations. It captures `props`, so the root props value moves to the heap
  too, which is the ninth. B's content fields have the concrete
  `ktml.ComponentFunc` type, so nothing escapes and B makes 0 allocations. The
  static `title` fills of `NestedSlots` capture nothing and do not allocate in
  any API. This is the per-fill cost ADR-0003 predicted ("one allocation per
  fill"). Since 2026-10-20 the H tree lowers these fills to one-pointer
  structs instead of closures, and H makes 1 allocation (the root props) on
  the nested rows; see ADR-0003's
  [Fill allocations](../../docs/adr/0003-rendering-api.md#fill-allocations-2026-10-20).
  The tables here keep the earlier numbers.
- **Cross-package calls: A 279 ns vs H 323 ns (`NestedCross/w=discard`), so H
  is 16% slower** (12% with the buffer), the reverse of the ADR's spike. The
  cause was not profiled. In both APIs each level runs the public `Render`
  with `rt.Wrap`/`rt.Finish`. H passes the 24-byte `Box` by value to a
  concrete method; A boxes `BoxProps` into the constructor's interface value
  and calls through it. Same-package calls (`NestedSame`) are static in both,
  and A and H tie there.
- **Templ.** A and H are 0.10–0.41× templ on every row except `ScriptHeavy`
  (0.59× with `io.Discard`, 0.93× with the buffer; templ re-encodes the JSON
  through `encoding/json` straight into its pooled buffer). Allocations are
  between 0 and 13% of templ's on every row.
- **Handwritten.** The lower bound is 1.2–4.9× faster than B: it skips
  context checks, the key preflight (whose map is most of the 54 KB/6 allocs
  of `ListHeavy` and the 1.2 KB/4 allocs of `ScriptHeavy`), typed errors,
  and the `rt.Writer` wrapper.
- **`FormHeavy` allocates 95 times in every API.** Each `ktml.Ptr(…)` for a
  supplied optional or defaulted input escapes, because the callee's props
  contents flow into the `io.StringWriter` interface call (see generator
  findings below).

### Generator findings

No generator bug changes output: all five implementations are byte-identical.
These are performance and robustness gaps found while building the module:

1. **`ktml.Ptr` literals allocate per call.** A supplied optional or
   defaulted input is passed as `ktml.Ptr(value)`. `ktmlRenderX` leaks the
   contents of `props`, because values reach `w.WriteString` through an
   interface, so every pointee escapes. `FormHeavy` makes 95 allocations per
   render in A, H, and B, against 1 for handwritten. Constant literals could
   be package-level values. They are safe because generated code never
   mutates props.
2. **A/H slot fills move the caller's props to the heap.** A fill closure
   captures `props`, and the closure escapes into the `ktml.Component` field,
   so the props escape too. That is one extra allocation per component with a
   dynamic fill, on top of one per fill.
3. **Fill closures drop `rt.Wrap` ownership** (`w, _ := rt.Wrap(ktmlW)`).
   When Go code renders a KTML fill with a writer that is not an `*rt.Writer`
   (a templ parent, or a test), the pooled writer is never released, and
   `Partial` is not recorded for that call.
4. Mixed attribute interpolation (`aria-describedby="{name}-hint"`) is
   lowered with `rt.Text` rather than `rt.Attr`. The bytes are the same, so
   this is cosmetic.
5. The compiler does not lower `JSONValue` and `TrustedScript`, which is why
   `ScriptHeavy` is hand-lowered (expected; outside this slice).

A syntax trap, not a bug: `a href="…" download "Download"` is the attribute
`download="Download"` (the `name "value"` form). The valueless attribute
followed by text needs the continuation form: `a (… download) "Download"`.
